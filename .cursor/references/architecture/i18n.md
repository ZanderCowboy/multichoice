# Localization (slang)

## Layout

| Path | Role |
|------|------|
| `apps/multichoice/lib/i18n/en.i18n.json` | English source strings |
| `apps/multichoice/lib/i18n/nl.i18n.json` | Dutch translations |
| `apps/multichoice/lib/i18n/strings.g.dart` | Generated — do not hand-edit |
| `apps/multichoice/lib/i18n/localize_core_message.dart` | Maps core English errors to `context.t` |
| `apps/multichoice/slang.yaml` | slang config (`base_locale: en`) |

## UI strings

- Add keys to `en.i18n.json` and `nl.i18n.json` (keep keys in sync).
- Use `context.t.<section>.<key>` in presentation/widgets.
- Import `package:multichoice/i18n/strings.g.dart`; app root wraps `TranslationProvider`.

## Core boundary

- `packages/core` emits **English** user-facing strings (validation, auth, feedback errors).
- Presentation maps them via `localizeCoreMessage(context, message)` — do **not** add `slang` to `packages/core`.
- New core messages: add English string in core, add matching case in `localize_core_message.dart`, add keys under `errors` / `validation` in both locale files.

## Codegen

- After editing `*.i18n.json`: `make slang` or `melos slang` (also runs as part of `make db` / `make fb`).
- Generated artifact: `strings.g.dart` — same hand-edit rule as other codegen.

## Locales

- Shipped: `en`, `nl`. Device locale via `LocaleSettings.useDeviceLocale()` in `run_multichoice.dart`.
